# معماری DigiPrice

## مرزهای نسخه MVP

نسخه فعلی یک برنامه ASP.NET Core با سه بخش است:

- **DigiPrice.Core**: مدل‌های دامنه و موتور محاسبه قیمت؛ بدون وابستگی به شبکه یا دیجی‌کالا.
- **DigiPrice.Api**: Minimal API برای سلامت سرویس، مدیریت نمونه کالاها و پیش‌نمایش قیمت.
- **Dashboard**: رابط فارسی راست‌چین در `wwwroot/index.html`.

کاتالوگ فعلی در حافظه است و صرفاً برای توسعه و نمایش کاربرد دارد. این معماری برای تولید تجاری کافی نیست و نباید مستقیماً روی اینترنت عمومی منتشر شود.

## مسیر معماری هدف

1. لایه هویت و مجوزها: ثبت‌نام، ورود امن، MFA برای مدیران و کنترل دسترسی.
2. مدل چندمستاجری: هر فروشنده tenant مستقل با محدودیت دسترسی در سطح query و سرویس.
3. ذخیره‌سازی پایدار: PostgreSQL، migrationها، تراکنش و تاریخچه تغییرات.
4. مخزن اسرار: رمزنگاری توکن‌های فروشنده با کلید مدیریت‌شده؛ عدم بازگرداندن توکن به کلاینت.
5. آداپتور دیجی‌کالا: تفکیک API رسمی فروشنده از جمع‌آوری اطلاعات عمومی؛ محدودیت نرخ، timeout، retry و circuit breaker.
6. موتور قیمت‌گذاری: تابع خالص و قابل تست؛ واحد پول ثابت؛ کف/سقف، حداکثر تغییر، هزینه‌ها و سیاست‌های فروشنده.
7. صف کار: پردازش زمان‌بندی‌شده و جلوگیری از اجرای هم‌زمان چند تغییر برای یک کالا.
8. دروازه تغییر: پیش‌فرض تأیید انسانی؛ اجرای خودکار فقط با رضایت صریح، سقف تغییر و کلید توقف اضطراری.
9. ممیزی: ثبت پیشنهاد، دلیل، تأییدکننده، پاسخ سرویس و نتیجه راستی‌آزمایی؛ بدون ثبت اسرار.
10. پایش: سلامت اتصال، نرخ خطا، تأخیر، هشدار و سنجه‌های مصرف.

## اصول تصمیم‌گیری

- هر قیمت به تومان و عدد صحیح است؛ تبدیل ریال/تومان فقط در آداپتور مرزی و به‌صورت صریح انجام می‌شود.
- قیمت رقیب و قیمت خود فروشنده دو منبع جدا هستند.
- ناموجود بودن قیمت رقیب نباید به صفر تبدیل شود.
- بای‌باکس فقط یک سیگنال رقابتی است؛ پایین‌تر بودن قیمت تضمین‌کننده برنده‌شدن نیست.
- تا زمانی که نتیجه نوشتن قیمت تأیید نشده، همان عملیات نباید کورکورانه تکرار شود.
- استراتژی «حداکثرسازی قیمت» تضمین فروش یا سود نیست؛ صرفاً هدف قیمت را در محدوده مشخص می‌کند.
